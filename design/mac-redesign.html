Tilde for Mac: three redesign directions

A review page for the owner. The iPhone app stays exactly as it is. This page proposes a new Mac design in three directions, each shown as macOS 26 windows at 1280×800 with the same demo data as the App Store screenshots. Nothing gets built until one direction (or a mix) is approved.

What's wrong with the Mac app today

  1. It's the iPad layout at Mac size. Sidebar rows are two lines of 15 pt bold SF Mono, about 62 pt tall, so only 14 servers fit in an 800 pt window. Mac-density 26 pt rows fit about 28. DESIGN.md §4 already targets 28 pt rows on the Mac.
  2. The same server appears up to three times. In the screenshot, prod-api-01 is listed under Live, Favorites and Production at once, with two different latencies (23 ms and 72 ms). The list looks like data you can't trust.
  3. The toolbar is shaped like iOS. Three separate round glass buttons (+, ⋯, sidebar) sit over the sidebar. A second + at the far right does something different (New Tab, not New Server). Latency, Snippets and + float as unrelated circles.
  4. Red appears everywhere at once. A PROD session draws a full-height red rule down the edge of the terminal, on top of the red tab and three PROD badges in the sidebar. When everything is loud, the warning stops working.
  5. Utility windows open as modal sheets. Keys and Snippets open as sheets over the terminal, from icon-only buttons in the sidebar footer. On the Mac they belong in their own windows (⌥⌘K / ⌥⌘S, DESIGN.md §3.4) and in the menu bar.
  6. Monospace is used for chrome. Tag chips (with "All" as a fake tag), tab hints and the editor's labels are all SF Mono. Labels and controls should be SF Pro, so the machine data stands out.
  7. The server editor is an iOS form. It has inset-grouped cards, a full-width five-way segmented control, "New group…" as a list row and oversized mint capsule buttons. Favorite and every Advanced field are below the fold, and there is no Test Connection.
  8. The tabs don't act like Mac tabs, and there's no status area. Tabs are rounded cards with colored tops and always-visible ⌘ hints, and the session title is repeated in the toolbar. Cipher, key, terminal size and reconnect state have nowhere to live.

Principles for the new Mac design

  1. Mac density, Mac controls. 13 pt SF Pro chrome, 24–28 pt rows, and pop-up buttons, checkboxes and radio groups instead of touch controls.
  2. One place for each thing. A server appears once. Latency, environment and sync each have exactly one home on screen.
  3. The terminal is the document. Opening a session hides the sidebar. Closing the last tab brings the server list back.
  4. Danger is a signal, not a theme. PROD always gets the same small set of markers: the tab stripe, a badge by the title and a status segment. Nothing louder, except the full-screen takeover when a host key changes, which stays.
  5. Keyboard first, complete menus. Every action is in the menu bar with its shortcut. ⌘K reaches all of them, and shortcut hints appear where your eyes already are.
  6. Native first. Use custom views only where SwiftUI has no answer: the tab strip, the status line and the palette.
  7. The brand is the accent and the type. Mint marks focus, live sessions and the primary action. SF Mono is for machine data only (names, hosts, ports, fingerprints).
Directions
A

Source ListA native Mac utility: a real sidebar, flat Mac tabs and a status bar, the way the rest of macOS does it.

The sidebar becomes a proper source list. It has one compact row per server (status, name, environment, latency), groups as collapsible sections, tags as filters, and Quick Connect in the sidebar's own search field (⌘L). Favorites get a star and float to the top of their group, so nothing is listed twice.

Sessions open as flat, full-width Mac tabs under a unified toolbar. A status bar finally gives latency, cipher, key and terminal size a single home. Opening a session hides the sidebar. When the last shell exits, the sidebar comes back next to a start page with recent connections and the health of each environment.

Lowest risk: almost everything is stock SwiftUI (List(.sidebar), .searchable, Form, Settings), and every Mac user already knows how it works.
Keeps the brand: mint accent and SF Mono for data, with Mac controls everywhere else.
Its pieces (de-duplicated sidebar, status bar) could move to iPad later at no extra cost.
The least distinctive of the three. It looks like a very good Mac app, not a new idea.
With the sidebar open you lose ~260 pt of terminal width (126 instead of 160 columns at 13 pt).
The start page is a second "home" next to the sidebar, and it has to earn its place.

A·aMain window: five sessions, sidebar visible

prod-api-01 is selected. Every server appears exactly once. Live sessions show a mint dot, and PROD is marked by the tab stripe, the badge next to the title and the status-bar segment, with nothing else.

Floating Liquid Glass sidebar (macOS 26), 248 pt wide with 26 pt rows. Names in SF Mono 12, everything else in SF Pro.
Search is Quick Connect. Typing deploy@10.0.4.12:2222 puts "Connect to…" as the first row. #k8s and env:prod become search tokens.
One row per server. The star marks a favorite and sorts it first in its group. The mint dot means a session is open, and the latency is from the last probe.
Toolbar: title in SF Mono with a PROD badge and the address as the subtitle. Snippets and New Tab share one glass group, the native Tahoe look.
Flat Mac tabs: full width, a 2 pt environment stripe on top, a faint red wash on PROD tabs, ⌘-number at the right, and close (×) on hover at the left.
Status bar (24 pt): environment, address, jump host and key on the left; latency, cipher, size and encoding on the right. Latency lives only here.
Sidebar footer is status, not buttons: iCloud sync state. Keys, Snippets and Settings move to the menu bar and their own windows.

A·bSession focus: sidebar hidden

Opening a session from the sidebar collapses it (columnVisibility = .detailOnly). ⌃⌘S or the toolbar button brings it back. If you re-open it by hand, Tilde won't hide it again in that window until every tab is closed.

The traffic lights and the sidebar toggle move into the toolbar, and the tabs span the full width. You get 160 × 43 at 13 pt.
A one-time HUD explains what happened. It never appears again after the first two times.
db-primary (PROD, via bastion) is in psql. Its tab, title badge and status segment are red, and the other tabs keep their own colors.

A·cHome: no sessions open

After exit in the last tab, the tab closes, the sidebar slides back and the detail shows a start page: a large Quick Connect field, recent connections and environment health. The sidebar is the server list. The start page answers "where was I, and is anything wrong?".

A banner records what just happened ("prod-api-01: shell exited (0)"), with ⇧⌘T to reopen it.
Recent is a native Table: double-click or ↵ connects. Columns are name, address, environment, last used and latency.
Environments: one card per environment with reachability. Staging is amber because staging-web is slow (183 ms).

A·dNew Server sheet

A Mac form, not an iOS one: a grouped Form with pop-up buttons, a horizontal radio group, checkboxes, a token field for tags and a small table for environment variables. All fields fit without scrolling. Return triggers Save & Connect.

Host and Port share a row. Pasting ssh -p 2222 -J bastion deploy@10.0.4.12 into Host fills every field it can.
Environment is a pop-up with colored dots, not a five-way segmented control. Picking Production also sets "Confirm multi-line paste".
Advanced is a disclosure group and remembers whether it was open. Startup command, tmux and TERM are visible at a glance.
Test Connection does the handshake, host key and auth, then reports the result inline.

A·eSettings window (⌘,)

The standard Settings scene with toolbar tabs: General · Terminal · Security · Sync · Known Hosts. Each pane is a grouped Form that reuses the existing section views. The new sidebar behavior is a setting under Terminal › Window, so it can be turned off.

General: appearance, default user and key, connect timeout, auto-reconnect, reachability probe, import of ~/.ssh/config and known_hosts.
Terminal (shown): theme with a live preview, font, cursor, bell, scrollback, paste confirmation, Option as Meta, copy on select, and the sidebar behavior.
Security: app lock, hide content when inactive, strict host checking, legacy ssh-rsa, clipboard clearing. Sync and Known Hosts are shown in B and C.

A·pCommand palette (⌘K / ⌘P) and unknown host key

The palette is a floating glass panel over the window. The host-key prompt is a sheet attached to the window. It never dismisses itself and holds the handshake open for up to 120 s.

The query parses as an address, so Connect comes first. Matching servers (user deploy) and actions follow. Shortcut hints appear on the right of each row.
The host-key sheet shows the fingerprint in mono, randomart in a disclosure, and the ssh-keygen command to check it on the server. Trust & Connect is the default button.

A·LLight mode (Settings › General › Appearance: Light)

The same window as A·a, using the light tokens from DESIGN.md §2.2 and the "Tilde Day" terminal theme. Environment colors move to their darker light-mode values, so PROD stays clear on white.

B

StatuslineTerminal first: a thin title bar, sessions on a bottom line, everything else summoned from the keyboard.

The window is a terminal and two thin lines. At the top is a 38 pt compact title bar. At the bottom is a 28 pt session line holding the tabs as numbered segments, where 1–9 match ⌘1–⌘9, plus latency and sync. The ordering is borrowed from how people already read tmux.

⌘K is the main way to navigate (servers, sessions, #tags, >actions, !snippets), and ⌘0 slides in a narrow server drawer. Home is a keyboard launcher. The New Server sheet shows the matching ssh command and ssh_config block live as you type. The host-key prompt appears inside the tab, so other sessions keep working.

The most terminal space: 160 × 45 at 13 pt with the drawer closed.
The strongest identity for the devops audience, and every action is reachable without the mouse.
Prompts scoped to a tab (host key, paste confirmation) never block the other sessions.
Tabs at the bottom are unusual on the Mac, and they sit right under tmux's own status line when tmux is running.
Mouse-first users discover less. The drawer and palette have to be learned.
Needs the most custom views: the session line, the launcher and the in-tab prompt.

B·aMain window: drawer open (⌘0)

The drawer is a narrow, keyboard-driven list. Each row shows the session numbers that server is open in, so [5] means "⌘5 takes you there". The env rail on the left edge of each row replaces badges.

Compact title bar (.unifiedCompact): the title is centered with its PROD badge. "Go to… ⌘K" opens the palette.
A 2 pt env line runs under the title bar for the active session. This is the only wide band of color, and it's the color of the session you're typing into.
Session line: numbered segments with env underlines. The selected segment is filled, and latency, size and iCloud state sit on the right.
Drawer rows are 24 pt and all mono, with a 3 pt env rail and tab numbers. Group headers keep the DESIGN.md caps style.

B·bSession focus: drawer closed

This is B's default state. The only chrome is 38 pt at the top and 28 pt at the bottom.

B·cHome: the launcher

With no sessions open, the window becomes the server list: a prompt-styled field over every server, grouped and navigable with the arrow keys. ↵ connects, ⌘↵ opens in a new window and ⌘E edits. Exiting the last shell lands here.

B·dNew Server sheet with a live ssh preview

A wide sheet. The form is on the left. On the right is what the form means: the one-line ssh command and an ssh_config block, both copyable. It teaches newcomers and reassures experts.

B·eSettings: Known Hosts pane

Settings is the same native scene in every direction. Here the Known Hosts pane is a real Table with search, sorting, multi-select and an import from ~/.ssh/known_hosts.

B·pCommand palette and the in-tab host-key prompt

The palette drops from the title bar and has typed scopes. The host-key prompt is an overlay inside the new tab, not a window sheet, so the other four sessions stay usable while you check the fingerprint.

C

FleetSessions in the sidebar, servers in a table, details in an inspector.

C separates what's open from what exists. The sidebar holds scopes (All Servers, Favorites, Recent, groups and tags) and the open sessions as vertical tabs. The server list is a full, sortable Table with an Inspector, like Finder or Activity Monitor. Double-click a row to connect.

When the sidebar hides for focus, the sessions move into the toolbar as compact tab pills. New Server and Edit happen in the inspector, next to the table, so you can see the rest of your servers while you fill it in.

Scales best: 50+ servers sort and filter in a table, and 10+ sessions read well as a vertical list.
The inspector shows the host key, the key in use and the jump host without opening a form.
Table, inspector and sidebar are all native, and the terminal gets the most rows because there's no tab strip.
Two places for tabs (sidebar, or toolbar when the sidebar is hidden) is more to learn.
Editing in a 300 pt inspector is cramped for environment variables and long startup commands.
Needs a wide window for Home with the inspector open (≥ 1180 pt). On a 13" laptop the inspector covers part of the table.

Why A

  • It fixes every problem on the list with the fewest new ideas: density, duplicates, the iOS toolbar, too much red, sheets for utilities, iOS controls and the missing status area.
  • It is mostly stock SwiftUI. On macOS 26 that means Liquid Glass, accessibility, full keyboard access and future OS changes come with it. The only custom views are the tab strip and palette (both exist) and a small status bar.
  • It keeps the brand that people like on the iPhone: dark ink, mint, SF Mono for data and the same environment badges. Only the density and the controls change.
  • Auto-hiding the sidebar gives A the focus of B whenever you're in a session, so the main argument for B is mostly covered.
  • Borrow from B: (1) put the unknown-host prompt inside the tab (B·p) instead of a window-modal sheet, so a slow fingerprint check never blocks the other sessions; (2) add the one-line ssh preview to the editor footer (B·d), copyable.
  • Keep from C for later: if users report 30+ servers, the A start page can grow a "Show all" button that opens C's Table view.

iPhone and iPad

  • iPhone: unchanged. PhoneRoot, ServerList, SessionDeck and the key bar are untouched. Every Mac change is behind #if os(macOS) or lives in new Mac-only files.
  • iPad: unchanged by default. iPad shares SplitRoot, ServerList and TabStrip with the Mac today, so the Mac sidebar is a new view and does not modify ServerList.
  • Worth offering iPad later (separate decision): the de-duplicated sidebar (one row per server, a star instead of a Favorites section), which is clearly better on any screen, and the status bar when a hardware keyboard is attached.

Open questions for the owner

  • Should Favorites be a star plus filter (proposed), or keep its own section at the cost of listing servers twice?
  • A uses macOS sentence-case sidebar headers ("Production") instead of DESIGN.md's caps. Is that OK on the Mac only?
  • Is a start page wanted, or should Home be just the sidebar plus an empty state?
  • Should the Mac stay dark by default, or follow the system appearance? DESIGN.md says dark everywhere.

Risks

  • Sidebar search on macOS 26: .searchable(placement: .sidebar) with tokens and suggestions needs a spike to confirm the ⌘L focus behavior and that the "Connect to…" suggestion row can be the default.
  • Colored dots in pop-up menus: NSMenu renders SF Symbols as templates, so the env pop-up needs non-template images. Small, but easy to miss.
  • Forced dark appearance on Liquid Glass: the floating sidebar and glass groups have to be checked for text3 contrast over the terminal ink background.
  • Auto-hide rules must never fight the user. Hide only when a session is opened from the sidebar or Home, never re-hide after a manual show, and show again when the last tab closes.
  • Shared code with iPad (SplitRoot, ServerList, TabStrip): keep it behind #if os(macOS) and compare iPad screenshots before and after.
  • Tag token field needs an AppKit bridge. If NSTokenField fights SwiftUI focus, the fallback is the existing chips plus a TextField.

What I was unsure about

  • The macOS 26 metrics (floating sidebar inset, corner radii, glass opacity) are close approximations drawn by hand, not traced from Apple's templates.
  • I kept server names in SF Mono everywhere (DESIGN.md's "data is mono" rule). If the Mac should look plainer, SF Pro names in the sidebar are a one-line change.
  • I couldn't trace the source of the red vertical rule beside the terminal in the current screenshots (it isn't the tab EnvStripe). The redesign doesn't use it either way.
